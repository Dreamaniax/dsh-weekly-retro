# dsh-weekly-retro · UI 设计评审（v0.4.2 现状）

> 评审基准：1440×900 真实浏览器截图（`docs/screenshots/`）+ 当前 `lib/client.js` 布局与样式。
> 目标：在不牺牲信息完整性的前提下，提升 **信息密度、视觉层级、交互可发现性、跨页一致性**。
> 本次只出评审与方案，不改代码。

## 0. 总体判断

| 维度 | 现状分 | 判断 |
|---|---:|---|
| 视觉美感 | 6.5/10 | 色板与 hero 已有设计感，但"一张图一张卡"导致大面积空白 |
| 信息架构 | 6/10 | 五 Tab 语义清楚，但页内没有二级导航、排序、筛选、下钻 |
| 交互逻辑 | 5.5/10 | 目前以"看"为主；图表不可点、列表不可筛、状态缺少反馈 |
| 一致性 | 6/10 | 中文界面里混入 `all/skill/plugin`、ISO 时间、`W46` 等原始值 |
| 可访问性 | 7.5/10 | 对比度/aria/tooltip 已收口；缺键盘下钻、focus ring、aria-live 进度 |

**最影响观感的三件事**

1. **顶部身份重复**：hero「本周洞察」+ 面板头「周报 / 2026-W46 / 今天昨天」+ hero 里再次出现周信息，首屏 170px 被重复信息吃掉。
2. **一图一卡、纵向堆叠**：概览 7 张全宽图表卡，900px 视口下内容高约 2088px；首屏只能看到 2–3 张图。
3. **图表与列表重复**：画像/重复/候选/历史都是"上面条形图 + 下面同样的卡片列表"，信息重复、页面被拉长。

## 1. 全局问题（跨 5 页）

| # | 问题 | 建议 |
|---|---|---|
| G1 | 顶部三层身份重复 | 合并为一个 sticky header：周次 + 新鲜度 + 主操作；hero 只保留一句洞察摘要 |
| G2 | 卡片全宽、纵向单列 | 建立 12 栏栅格；概览 2 栏、画像/重复 2 栏或表格、候选单栏但紧凑、历史表格式 |
| G3 | 所有卡片同一视觉权重 | 分 primary/secondary/tertiary 三级：KPI 数字 > 图表 > 说明文字；减少边框，用背景层级分组 |
| G4 | 图表不可交互 | hover 显示数值 tooltip；点击图例/柱/扇区过滤下方列表；提供"查看全部" |
| G5 | 空/加载/错误状态弱 | 骨架屏 + 空状态插画/说明 + 错误重试；运行中用 aria-live 播报 |

| # | 问题 | 修改建议 | 优先级 |
|---|---|---|---|
| O1 | hero 170px + 面板头重复周信息 | 合并为 64–72px 的 sticky header：`2026-W46 · 今天/昨天 · 刷新 · 运行▾`；hero 只留一句「本周 3 个候选可落地」 | P0 |
| O2 | KPI 6 卡排成 3×2，单卡过宽 | 1440 宽排 6 列（`flex:1 1 0`），窄屏 3×2；数字 24px、标签 10px；卡高 ≤72px | P0 |
| O3 | 运行区 3 个等权按钮占一整卡 | 收成工具栏：主按钮「运行」+ 次按钮「刷新」；"只重跑/全量"放下拉；显示上次运行时间/结果 | P1 |
| O4 | 7 张图一图一卡，页面 2088px | 2 栏栅格：会话构成 + 轮次构成并排；压缩直方图 + 候选形态并排；漏斗/热力/工具用量按整行或 2/3 栏 | P0 |
| O5 | Donut 104px 放在 200px 卡里 | 缩到 72–80px，图例右侧内联；卡片高度 140–160px；去掉多余空白 | P0 |
| O6 | 压缩直方图分桶标签 `0/1/2/3+` 难懂 | 标题改「每会话压缩次数」；轴下加「次」；0 值柱保留细线并显示 0 | P1 |
| O7 | 热力图没有刻度/图例 | 加 00/06/12/18/23 刻度 + 低→高色阶图例；hover 显示 `14:00 · 42` | P1 |
| O8 | 漏斗只是 5 根横条 | 改真正漏斗/阶梯图：每步转化率 + 流失量；"本周候选→已落地"高亮 | P1 |
| O9 | 分区标题 11px、无信息量 | 标题加计数/单位，如「会话构成 · 12」「压缩 · 3 次」；右侧放"查看报告"锚点 | P2 |

## 3. 画像（Portrait）· 8 个修改点

| # | 问题 | 修改建议 | 优先级 |
|---|---|---|---|
| P1 | 顶部条形图与下方卡片完全重复 | 删除条形图，改成一行摘要：「5 条主线 · 覆盖 12 会话 · 3 条有产出」+ 排序控件 | P0 |
| P2 | 每条主线一张全宽大卡，3 行内容占 160px | 改 2 栏卡片或紧凑表格；卡高 ≤120px；标题/目标/证据/产出四行内 | P0 |
| P3 | 卡片之间无排序、无筛选 | 按证据数/产出数/最近活跃排序；支持"只看有产出/有目标" | P1 |
| P4 | 证据会话是 3 行 mono 文本 | 换成 chips（标题 + id 尾号），默认 3 个 + `+N`；点击打开会话详情 | P1 |
| P5 | 无详情视图 | 卡片点击打开右侧 Drawer：完整目标、产出、全部证据会话；保留列表滚动位置 | P1 |

| # | 问题 | 修改建议 | 优先级 |

| C4 | 卡片信息层级平 | 标题 13px 加粗；verdict badge + 总分右侧；摘要 2 行；展开显示 4 维评分与理由 | P1 |

## 8. 评审结论

- **不是"再加图表"，而是先减重复、再提密度、最后加下钻。**
- 当前最大杠杆：**概览 2 栏栅格** + **画像/重复表格化** + **历史图表修复**；这三项能把"像 Demo"提升到"像产品"。
- 建议先做 B1，再根据你的偏好决定 B2 的下钻形态（Drawer vs 新页面）。
